# YouTube の伸ばし方（11/22 未明・ユーザー「時間を掛けたほうが良い？Claude で YouTube をやる手段を調べて」）

## うちの数字（docs/video-metrics.tsv・GA）
- ショート約100本: 1本あたり 100〜1,200回で頭打ち（1,000回前後が上限）。継続は 比べる型・在庫ランキング・電池が 25〜43% と高く、予算別・世代差は 12〜20%。**登録はほぼ0**（チャンネル計13人）
- 横動画 約25本: 6〜717回。伸びたのは Pixel 1年あたり 717（検索・ブラウジング）・地雷 342・何世代まで 341・予算別 288。新型の比較（M6・mini・Duo）は 11〜86
- サイトへ: YouTube から 28日で約32セッション・店クリック 15回/6人（ChatGPT は 531回）
- 作業の重さ: ショート2本の予約だけで作業役が 139操作・7分（ブラウザで YouTube Studio を操作しているため）

## 外の情報（ベンダーの調査なので数字は目安）
- 小さいチャンネルはショートで見つけてもらい、横動画で視聴時間と登録を得る、が一般的な役割分担（vidIQ）
- ショートは月5本前後で横動画の再生が上がり、月35本を超えると効果が消える、という調査あり（Metricool）。うちは月約60本
- Claude で YouTube を扱う手段: YouTube Data API／Analytics API をつなぐ MCP（有志）、公開データを読むプラグイン（TubeAlfred・Manifold。Anthropic ディレクトリ・コミュニティ製）。公式の Anthropic 製はない

## 読み
1. **今の形では、YouTube に時間を足してもサイトの収益はほとんど増えない**。ショートは再生されても登録・サイトの訪問につながっていない
2. 伸ばすなら「量」より「検索で見つかる横動画」。伸びた横動画はどれも、人が検索する問い（何世代まで・地雷・安いPixelは損？）
3. いちばん効く改善は手間の削減: 数字は YouTube Analytics API で取れば、ブラウザ操作なしで毎日読める

## 打ち手の案
1. **YouTube Analytics API（読むだけ）をつなぐ**。OAuth の同意はユーザー（Google Cloud で1回）。数字取りと判定がブラウザなしになる
   - アップロードの API は、監査前のプロジェクトだと動画が非公開に固定されるので、当面ブラウザのまま
2. **ショートを1日2本→1本に戻し**、浮いた時間を横動画の「検索される問い」選びに回す（試しに2週間・横動画の再生と登録で判定）
3. 横動画のネタは YouTube 検索の候補（サジェスト）から選ぶ。新型の比較（検索されにくい）は減らす
